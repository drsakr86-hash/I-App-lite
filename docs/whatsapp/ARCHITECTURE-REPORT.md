# مساعد واتساب الرسمي — تقرير المعمارية والتنفيذ

**الحالة:** كود وتصميم قاعدة بيانات جاهزان على فرع `feature/whatsapp-assistant`. **لم يُطبَّق شيء على الإنتاج، ولم يُنشر شيء، ولم يُختبر إرسال فعلي عبر Meta.** كل اختبار مذكور هنا مصنَّف (وهمي / قاعدة بيانات محلية حقيقية / حي) في `TEST-REPORT.md`.

## 1) ما الموجود فعلاً وسنعيد استخدامه
| الموجود | الاستخدام |
|---|---|
| جدول `iapp_appointments` (السلطة الوحيدة للمواعيد) + قيد منع التكرار + `iapp_has_role` + جدول `iapp_staff` | الحجز/الإلغاء/التعديل تتم على نفس الجدول، والصلاحيات من نفس الأدوار (admin/secretary) |
| `iapp_booking_requests` وبوابة حجز المريض (`PATIENT_CLINICS`) | مصدر جداول العيادات (نسخة في `schedule.js` + اختبار يكشف أي اختلاف) |
| `iapp_store` (`iapp_prices`, `iapp_doctors`) | أسعار وأطباء حقيقية للمساعد، بدون تكرار |
| Supabase (RLS، pg_cron، pg_net، vault) | قاعدة البيانات والجدولة والأسرار — بدون خادم جديد |
| نظام الصلاحيات والتبويب في التطبيق (`More`، `SecretaryApp`) | شاشة الصندوق بنفس الأنماط |

غير موجود وتم بناؤه: أي طابور رسائل، سجل محادثات، تدقيق واتساب، Edge Functions (لا توجد وظائف منشورة اليوم).

## 2) خيار الخادم
**Supabase Edge Functions** (Deno) — ثلاث وظائف: `whatsapp-webhook` (استقبال)، `whatsapp-worker` (معالجة + إرسال، يُستدعى كل دقيقة من pg_cron وفور وصول رسالة)، `whatsapp-send` (رد السكرتارية). السبب: الواجهة على GitHub Pages (ثابتة، لا تصلح لأسرار) والمشروع على Supabase أصلاً. الأسرار في Edge Function secrets فقط.

## 3) التدفق
`Meta → webhook (تحقق من التوقيع HMAC على الجسم الخام، تخزين دائم idempotent، رد 200 سريع) → worker (يلتقط الرسائل غير المعالجة) → طبقة الأمان الحتمية → النموذج بأدوات ضيقة → رسائل صادرة في الطابور → إرسال عبر Graph API → حالات التسليم ترجع بالـ webhook`.

* **جدول `wa_messages` هو السجل والطابور معاً**: مفتاح idempotency، الالتقاط بـ `FOR UPDATE SKIP LOCKED`، وكاسح للرسائل العالقة في `sending`.
* **نتائج الإرسال أربع**: `sent`، `retry` (Meta ردّت بخطأ مؤقت = لم تُقبل)، `failed`، **`uncertain`** (مهلة/انقطاع: قد تكون وصلت → لا تُعاد تلقائياً، وتظهر للسكرتارية بتحذير).
* **الحجز**: قفل استشاري لكل خانة (عيادة+تاريخ+وقت) داخل دالة SQL واحدة → اختبار 12 جلسة على خانة واحدة = فائز واحد.
* **وضعان للحجز** (`wa_config.booking_mode`): `request` (الافتراضي: طلب حجز تراجعه السكرتارية، والرسالة تقول صراحة أنه ليس تأكيداً نهائياً) و`direct` (حجز مؤكد).

## 4) أمان المساعد
1. **طبقة حتمية قبل النموذج** (بدون استدعاء نموذج): أعراض عاجلة ← رسالة طوارئ معتمدة + تحويل فوري؛ طلب موظف؛ رسائل غير نصية؛ حد معدل؛ «إيقاف» لإلغاء التذكيرات.
2. **النموذج يقترح فقط**: الأدوات للقراءة والاقتراح. أي كتابة تصير `pending` وتُنفَّذ **بعد «نعم» من المريض في رسالة لاحقة** (صلاحية 15 دقيقة) وبإعادة تحقق كاملة وقت التنفيذ.
3. **رسالة النجاح يكتبها الخادم** بعد تأكيد قاعدة البيانات فقط، وحارس مخرجات يمنع أي نص من النموذج يدّعي «تم الحجز».
4. **الهوية**: رقم المريض يأتي من Meta (ويُوقَّع) لا من النموذج؛ عرض/تعديل مواعيد قائمة يتطلب مطابقة الاسم المسجل؛ الإجابة عند الفشل واحدة (لا تكشف وجود موعد)؛ المراجع `A1…` معتمة.
5. **حقن التعليمات**: رسالة المريض تُغلَّف كبيانات غير موثوقة ويُنظَّف النص؛ مخرجات النموذج نفسها تُنظَّف وتُتحقق.
6. **حدود طبية**: لا تشخيص ولا علاج؛ الأسئلة الطبية → السكرتارية. نصوص الطوارئ قابلة للتعديل من الإدارة (`wa_config.urgent_message`) وتحتاج اعتماد الطبيب قبل التشغيل.
7. **خصوصية**: السجلات تحتوي معرفات وأكواد أخطاء فقط (مُختبَر)؛ الرسائل تُحذف حسب `retention_days`؛ لا تُرسل بيانات إكلينيكية للنموذج.

## 5) التذكيرات
دالة `wa_enqueue_reminders` (idempotent بمفتاح لكل موعد/فاصل) تعمل من pg_cron؛ تتطلب **موافقة صريحة** (`reminders_opt_in`) ولا ترسل لمن أوقف الرسائل؛ تُسحب تلقائياً لو أُلغي الموعد أو تغيّر؛ تعتمد **قالب Utility معتمد** من Meta (لا نص حر خارج نافذة 24 ساعة)، ومتغيراته: التاريخ والوقت والعيادة فقط.

## 6) الصندوق في التطبيق
`WhatsAppInbox.jsx` — للإدارة (من «المزيد») والسكرتارية (تبويب). قائمة + فلاتر + بحث + غير مقروء + تعيين + استلام/إعادة للمساعد (يمنع تنافس المساعد والموظف) + رد يدوي عبر `whatsapp-send` (يتحقق من الدور ونافذة 24 ساعة) + حالة التسليم وإعادة المحاولة + حجوزات الرقم (مؤكد/طلب) + موافقة التذكير. تظهر رسالة «غير مفعّل» إن لم تُطبَّق الجداول. لا علاقة لها بشاشة الطابور العامة.

## 7) الحد الأدنى من تغييرات قاعدة البيانات
ملف واحد إضافي فقط (`docs/sql/whatsapp-assistant.sql`): جداول `wa_*` + دوال + RLS. **لا يعدّل** `iapp_appointments` ولا أي سياسة موجودة. التراجع: `whatsapp-assistant-rollback.sql`. الجدولة: `whatsapp-cron.sql` (منفصل، قيم الأسرار placeholders).

## 8) المخاطر المعروفة
* **أرقام مصر والتعايش (Coexistence):** أهلية الرقم الحالي **لم تُتحقق** — المصدر الوحيد الذي وجدناه طرف ثالث. يُتحقق منها داخل Meta Embedded Signup قبل أي ربط (انظر `META-SETUP.md`).
* **المزامنة القديمة (last-write-wins):** كتابة المساعد على `iapp_appointments` مباشرة قد تتعارض نظرياً مع تعديل متزامن من جهاز غير متصل؛ نقلل الأثر بكتابات ذرّية قصيرة، ويُراقب في المرحلة التجريبية.
* **صيغة الوقت النصي** (`9:00` مقابل `09:00`): التطبيع في الكود وSQL؛ يُراجع على بيانات حقيقية في مرحلة staging.
* **فهم العربية الحي** لم يُختبر (يحتاج مفتاح نموذج ورقماً تجريبياً).
* **السعر:** قوالب Utility خارج نافذة 24 ساعة مدفوعة لكل رسالة؛ تكلفة النموذج لكل رسالة (Haiku افتراضياً)؛ استدعاءات Supabase Functions وpg_cron ضمن الخطة الحالية غالباً. أرقام الأسعار تُراجع من لوحة Meta وقت التفعيل.
