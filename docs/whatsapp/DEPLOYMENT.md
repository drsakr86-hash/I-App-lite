# قائمة النشر وخطة التراجع والتدرّج

## قائمة ما قبل النشر (كلها لازم تتحقق)
- [ ] موافقة المالك الصريحة على تطبيق SQL (staging أولاً).
- [ ] نسخة احتياطية من قاعدة الإنتاج (Supabase backup / PITR) قبل أي تطبيق.
- [ ] `npm test` و`npm run build` و`npm run test:whatsapp-sql` ناجحة على نفس الـ commit.
- [ ] التحقق من أهلية الرقم للتعايش داخل Meta (أو قرار رقم جديد).
- [ ] قالب `apt_reminder` معتمد من Meta.
- [ ] نص رسالة الطوارئ (`urgent_message`) والـ FAQ معتمدان من الطبيب.
- [ ] الأسرار في Supabase secrets فقط؛ لا شيء في Git (يوجد اختبار آلي يفحص ذلك).
- [ ] إضافة سطور `wa_faq` المعتمدة (تعليمات التحضير للكشف، إلخ) — بدونها يحوّل المساعد الأسئلة للسكرتارية.

## التدرّج المقترح
1. **محلي/آلي** — ✅ منجز (انظر TEST-REPORT).
2. **Staging**: مشروع Supabase فرعي (branch) + بيانات وهمية فقط + تطبيق SQL.
3. **رقم Meta التجريبي**: اختبار حي لكل بند في «ما لم يُختبر حياً»، وتسجيل الأدلة (wamid، لقطات حالات التسليم).
4. **تجربة محدودة بإشراف**: `enabled=true`، `ai_enabled=true`، `booking_mode='request'`، `reminders_enabled=false`، لعدد قليل من الأرقام (موظفين)، السكرتارية تراقب الصندوق.
5. **التذكيرات**: بعد نجاح (4) وتفعيل القالب، لمرضى وافقوا فقط.
6. **الإنتاج على الرقم الفعلي**: بعد موافقة صريحة، وبعد تأكيد التعايش، وبوضع `request` أولاً ثم `direct` إن رغبت.

## خطة التراجع (من الأسرع إلى الأعمق)
1. **إيقاف فوري بدون نشر**: `update wa_config set enabled=false;` — العامل يتوقف، والويب هوك يخزّن الواردات فقط، ولا يُرسَل شيء. (التطبيق يعمل كما هو والسكرتارية ترد من تطبيق واتساب.)
2. إيقاف المساعد فقط: `ai_enabled=false` (الصندوق والردود اليدوية تبقى) / إيقاف التذكيرات فقط: `reminders_enabled=false`.
3. إلغاء الجدولة: `select cron.unschedule('wa-worker');`
4. إلغاء اشتراك الـ Webhook من لوحة Meta (الرقم الأصلي لا يتأثر).
5. حذف الوظائف: `supabase functions delete whatsapp-webhook whatsapp-worker whatsapp-send`.
6. إزالة البيانات: `docs/sql/whatsapp-assistant-rollback.sql` (يحذف كائنات `wa_*` فقط؛ **لا يلمس المواعيد** — الحجوزات التي أنشأها المساعد تبقى مواعيد عادية). مُختبر محلياً: «rollback: clean».
7. الواجهة: إرجاع الفرع/الـ commit على GitHub Pages.

## أسماء الوظائف الفعلية على الإنتاج (النشر من لوحة Supabase يولّد أسماء عشوائية)
| الاسم على Supabase | الدور | Verify JWT |
|---|---|---|
| `swift-worker` | whatsapp-webhook (استقبال Meta) | OFF |
| `quick-task` | whatsapp-worker (معالجة + إرسال) | OFF |
| `hyper-responder` | whatsapp-send (رد السكرتارية؛ يتحقق من المستخدم والدور داخل الكود) | OFF |
* رابط الـ Webhook: `https://mofdveiwlaymlabvsypu.supabase.co/functions/v1/swift-worker`
* سر إضافي: `WORKER_FUNCTION=quick-task` (لتسريع المعالجة؛ الـ cron يغطي لو غاب).


## تنبيه: تغيير رقم الإرسال
عند تغيير الرقم يجب تحديث **ثلاثة** أشياء معاً: `wa_config.phone_number_id` (فلتر الاستقبال)، وSecret `META_PHONE_NUMBER_ID` (الإرسال)، وتعيين حساب واتساب (WABA) الجديد لمستخدم النظام صاحب التوكن. نسيان الثاني يسبّب `131030` عند الإرسال (حدث فعلاً 2026-10-21).
